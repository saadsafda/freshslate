13.1 WHAT OPENCLAW IS (ARCHITECTURE)

OpenClaw (formerly Clawdbot, then Moltbot) is an MIT-licensed, open-source personal AI agent that launched in late 2025 and became one of the fastest-growing repositories in GitHub history. Creator Peter Steinberger joined OpenAI in February 2026, with the
project transitioning to an independent foundation while remaining open-source under MIT.

It is not a chatbot. It is a local gateway process running as a background daemon on your machine or VPS, connecting messaging platforms to an LLM-powered runtime that takes real actions.

Three layers

Layer

What lives there

Fresh Slate use

Channel

WhatsApp, Telegram, Slack, Discord, Signal, iMessage, WebChat — all into one Gateway

You message your acquisitions agent from your phone while standing in a driveway

Brain

Instructions, personality, model routing. Model-agnostic — Claude, GPT, Gemini, or local via Ollama

Sonnet for reasoning, Haiku for cheap heartbeat checks, local model for PII

Body

Tools, browser automation, file access, persistent memory

Parish site navigation, document reading, deal file management

The Gateway runs as systemd on Linux or a LaunchAgent on macOS, binding by default to
ws://127.0.0.1:18789. It handles routing, authentication, and session management, and never touches the model directly.

The seven-stage agentic loop

Understanding this is what lets you debug at 11pm when a deal is on the line.

Channel normalization — adapters (Baileys for WhatsApp, grammY for Telegram) convert every input into one message object. Voice notes are transcribed before the model sees them.

Routing & session serialization — messages in a session process one at a time via a Command Queue. Concurrent messages would corrupt state.

Context assembly — the system prompt is built from base prompt + a compact skills list (names, descriptions, paths only) + bootstrap files + per-run overrides.

Model inference — standard API call, with a compaction reserve of tokens held free so the model never runs out mid-reasoning.

ReAct loop — model returns either text or a tool call. Tool call → runtime executes → result feeds back → model decides again. Reason, act, observe, repeat.

On-demand skill loading — the model reads a full SKILL.md only when it decides that skill is relevant. This is why you can install 40 skills without bloating context.

Memory & persistence — plain Markdown in ~/.openclaw/workspace/.
MEMORY.md for long-term facts, append-only daily logs at memory/YYYY-MM-DD.md. Embedding search via
sqlite-vec. Everything runs on SQLite and Markdown files.

Why the file-based design matters for us: every decision traces back to a file you can read, audit, and hand to an attorney. When LREC or opposing counsel asks what your system did and why, you have an answer. A closed SaaS agent cannot give you that.

13.11 WHAT THIS DOES NOT DO

Setting expectations honestly here prevents refunds and lawsuits later. Say this out loud on camera in the module.

It will not

Why

Close deals for you

It prepares; you decide and execute

Replace your attorney

It flags issues; counsel resolves them

Replace GHL, Make, or your voice stack

It orchestrates them, and it is worse at deterministic tasks than Make.com is

Run unattended

Human-in-the-loop is the design, not a limitation

Be reliably accurate on public records

It will misread documents. Citation discipline exists so you can catch it

Make you compliant

It reduces the odds of an error. Compliance remains yours

Honest assessment of where OpenClaw actually earns its keep in this business: monitoring, synthesis, and preparation — the work that is currently done badly or not at all because nobody has time. It is a very good analyst and a very bad closer. Deploy
it accordingly.
